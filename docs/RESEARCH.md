## 站得住（不依赖胜率测量）

### 对香草可用的第一手漏洞：只有三条，全是八云紫

```
間d1-e1    一手杀    需要：紫在后位 + 王位空着
間h1-e1    一手杀    需要：紫在车位 h1 + 王位空着
間h1xh8    白吃5分   需要：紫在车位 h1
```

**凭什么**：穷举。每个可部署棋子 × 每个合法部署格 × 每一手合法走法，
部署方只留王和被测子（自己绝不挡自己，取上界），对面整副香草。
阈值从「净赚 ≥4」放宽到 ≥2 也不增加。另有一万二千对随机部署的抽样
独立指向同一组。不下棋、不经过胜率、不依赖引擎估价。

**限制**：只覆盖「第一手成杀或第一手净赚」。叉子型（第二手兑现）不在表内 ——
camel 那条 `a2-b5` 同时叉 a8 和 c8 就是 4 层扫描抓到的，不是第一手抓到的。

**连带的设计准则**：香草底线只有 a8/h8 两格无保护，而部署制让远程跳跃子
一步从第 2 行进第 5 行。所以**新加能放兵位的棋子，先问它一手能不能进第 5 行**。
现有的兵位棋子全部枚举过，都安全。

### 角防御能完全杀死车位紫的突袭

马位爱丽丝 / 马位露米娅 / b2妖精 / b2恋 都能让 h1 紫**零合法走法** ——
不是「不划算」，是她作为将军对象不能自投攻击。

### 规则书与实现一致

25 个已实装棋子的 cost、部署位、数量限制、列限制全部对上（`lab/check_rules.py`，
0 处不一致）。唯一待决项见 `rules/open_questions.toml`。

## 站得住（相对比较：噪声两臂同等承受）

### 重子惩罚是阵容相关的，不能删也不能照原样留

```
                  全开     -heavy    关掉的变化
香草             55.8%    34.2%    -21.7pp  z=-2.44  (n=60)
灵梦3枚          36.9%    56.9%    +20.0pp  z=+2.59  (n=80)
```

同一项、两个阵容、符号相反、幅度相同。已据此改成**只约束滑行重子**
（后/车/早苗/衣玖/龙王），灵梦豁免 —— 她穿透、攻击圈在线外、永远有退路，
「被堵被赶」这条代价对她不成立。这个改动在香草上是空操作（它的重子全是
滑行子），在灵梦阵容上把「显著有害」消成中性。

**凭什么能信**：同一个阵容双方对摆、只切换一项，引擎自身的失误幅度
两臂同等承受，只放大方差不产生偏差。**绝对测量扛不住这个噪声，相对比较扛得住** ——
这是区分上一轮哪些数据能救、哪些不能的判据。

### 开局原则项合计净零，但不是「没用」

A/B 跨六个阵容 49.2%，CI[40,58]，n=120。净零的原因是其中一项对一半阵容
+20pp、对另一半 −20pp 被平均掉了。

## 最重要的一条：搜索慢了 16 倍，而那才是真正的约束

```
搜索耗时（5 个局面合计）
                        深度3      深度4      深度5
原始                   2052ms    14180ms    90511ms
+ 杀手走法/历史启发     1257ms     6844ms    32775ms    1.6× / 2.1× / 2.8×
+ 惰性合法性            339ms     1031ms     5722ms    6.1× / 13.8× / 15.8×
```

两处都**不改变搜索返回值**，所以 `tests/golden.test.ts` 的 280 项一字未变 ——
这是个很硬的判据，变了就是实现错了。

- **杀手走法 + 历史启发**：只改枚举顺序，而全窗口 alpha-beta 的根值与
  枚举顺序无关。分支因子从 6.9×/层 降到 5.4×/层。
- **惰性合法性**：`legalMoves` 原来对每个伪合法走法都 `applyMove`+`inCheck`，
  而 alpha-beta 通常试 1~3 个走法就截断 —— 每个结点白验证约 27 个。
  更糟的是它在 `d<=0` 之前就算完整表（为了认出将杀），所以**地平线结点
  （结点数的大多数）全额付费**。改成搜索走伪合法 + 惰性验证，地平线只问
  「有没有合法走法」（找到第一个就停）。

成本后果：

```
深度4 一局          720 秒  →  约 50 秒
深度4 验收(n=30)    6 小时  →  约 10 分钟
一个棋子标定(400局)  1600 小时 → 约 4 小时
```

**我被深度 2 困住从来不是真实约束，是引擎没优化。** 上一轮花一整夜用
分辨不出三个兵的仪器测了六千局，而根因只要 profile 一次就能看见。
按优化顺序这应该是第一件事，不是第八件。

还没做的（会改变返回值，所以要单独立判据）：置换表（需要增量 Zobrist
哈希，现在的 `posKey` 每个结点重建长字符串，拿它当表键反而更慢）、
空着法剪枝。

## 仪器定下来了：开发者级 = 固定深度 5

验收测试（少 3 个兵对香草；两边都无打入手，所以是真让子；基准 50%）：

```
配置                     少3兵   偏离50%   判定      三次重复   终局子力差
开发者级 深度3+少子加深   38.8%   z=-1.12  不通过      2.5%      -5.9
开发者级 深度4 固定       36.7%   z=-1.69  不通过       20%      -3.9
开发者级 深度5 固定       15.0%   z=-4.43  通过          0%      -8.6
贤者级   深度3+少子加深   25.0%   z=-2.51  通过（但有阵容相关偏差，不可用）
```

**3→4 只差 2.1pp，4→5 差 21.7pp —— 这是道坎，不是渐变曲线。**
深度 5 是引擎第一次能把子力优势转化成胜势的深度：优势从 −3.0 扩大到 −8.6，
零重复和棋，17/30 以将杀结束。深度 4 时 20% 的对局以重复和棋收场、
终局子力差只有 −3.9（优势被还回去了）。

成本 123 秒/局（2 核）。对照：优化前深度 3 是 71 秒/局 —— 所以那 16 倍
加速正好换来跨过这道坎的能力，代价不到以前深度 3 的两倍。

研究标准：`fixedDepth=5`。**固定深度而非少子加深**，因为测量仪器应当各阶段
一致；而我当初以为「残局收不掉有封盘裁定兜着」是错的 —— 三次重复在手数
上限之前就判和，裁定轮不到。深度 5 下这个问题自己消失了（零重复）。

### 我在这件事上判断错过两次

1. 「少3兵已有两份独立旁证（15.5%、15.0%），仪器这一关结论已相当明确」——
   错。那两次跑的是**带开局原则项**的配置，和开发者级不是同一件事。
2. 「3→4 只涨 2.1pp，所以问题在评估而非深度，加深度救不了」—— 错。
   我拿两个点外推一条趋势，而真实形状是阈值。4→5 涨了 21.7pp。

## 曾经卡住的地方：正确的设计在深度 3 上不够灵敏

验收测试（少 k 个兵对香草，两边都无打入手所以是真让子）：

```
少3兵 对 对照（51.2%, n=40）
  贤者级  有开局原则项   25.0%  CI[14,40]   -26.2pp  z=-2.51   通过
  开发者级 无开局原则项   38.8%  CI[25,54]   -12.4pp  z=-1.12   不通过
```

**带手写开局项的仪器通得过，不带的通不过。** 而带的那个恰恰不能用来
排名阵容 —— 它的偏差符号随阵容翻转（香草 +21.7pp、灵梦3枚 −20.0pp）。

这是「开发者级的设计必须正确」这条原则的真实代价。解法不能是把开局项
加回来（那就回到用有偏仪器量东西），只能是**加深度** —— 开局表现应该是
搜索深度的副产物，不是编码的原则。深度 4 的验收在跑。

两个顺带的结论：

- **对照格位的期望是恰好 50%**（两边阵容相同 + 奇偶局对调颜色）。
  实测 51.2%（n=40，偏 +1.2pp）证实无偏，所以后续验收可以直接拿 50%
  当基准，不必每次再跑 40 局对照 —— 验收成本减半。
- **子力响应几乎在第一个兵之后就平了**：第 1 个兵 −10.0pp，
  第 2、3 个兵合计只有 −2.4pp。这也是深度 3 分辨力不足的表现。

### 我在这件事上判断错过一次

我曾说「少3兵已有两份独立旁证（15.5% n=29、15.0% n=10），仪器这一关
的结论已经相当明确」。那是错的：那两次跑的是**带开局原则项**的配置，
和开发者级测的不是同一件事，我把配置不同的测量当成了同一件事的重复。
本次开发者级读到 38.8%，和那两次差 +23.3pp（z=2.28，显著）。

## 作废

### 点数表标定，约六千局，一个数都不能用

根因：搜索深度 2 的引擎分辨不出子力。最便宜的健全性检查给出：

```
白方少 k 个兵 对 香草（两边都无打入手，所以省下的弹药是死分，这是真让子）
  深度 2   少1兵 47.5%   少2兵 48.3%   少3兵 47.3%    毫无趋势 ← 不及格
  深度 3   少3兵 15.5%(n=29) / 15.0%(n=10)            方向和量级都对
```

少三个兵接近必败而仪器读不出来。这个检查最便宜，却是整个项目里最晚做的
一个 —— 我一直拿这把尺子去量棋子，从没量过尺子本身。

连带作废：amazon / 大主教 / ferz 的让子阶梯与不动点迭代，以及我中途报出
又自己推翻的三条结论：
- 「换兵的结构代价能解释低段偏低 0.3」—— 换马那组 800 局推翻
- 「amazon 共识偏高 2.8 分」—— 贴 50% 重测是 11.83，共识在区间内
- 「四个短程跳跃子值约 1.0，妖精该降到 1」—— 干净配对推翻，ferz 在 1.5 以上

**妖精 / 桑尼 / 露娜不要改价。**

### 协议上踩过的三个坑（新协议已避开）

1. **同价注册**：把被测子按被替换子的价格注册，本意是消掉循环论证，
   实际引入更大偏差 —— 引擎按错价处置自己的子。同一个物理局面，
   ferz 登记 1 分测出 50.5%、登记 1.5 分测出 59.1%，差 8.6pp。
   现在 cost 和 value 是两个字段，不会再混。
2. **配对拟合**：想从两个格位同时解出斜率和水平，而斜率落在分母上，
   n=160 定不住它，自助区间宽到没有判别力（ferz 第二轮 [-0.25, 3.33]）。
3. **让子格位的弹药**：拿掉子会把点数变成弹药。但**没有打入手时弹药
   花不出去**，所以那些让子是真让子 —— 我一度以为它们被补偿了因而推翻了
   深度诊断，是错的。

## 2026-10-25：当前 Hard 四局复测（0/1/20/79）
