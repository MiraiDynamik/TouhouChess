# 置换表

`engine/transposition.ts` 是唯一缓存实现，浏览器、Worker 和 CLI 均通过同一 TS 引擎使用。2026-10-28 用户授权默认采用1,048,576槽和较深结果复用；内部剪枝目前仅保留LMR。下文早期性能记录是在内部剪枝关闭时测得，不代表当前组合配置。参考 Stockfish 的局面索引、精确/上下界评分、最佳走法排序、记录年龄和将杀距离校正思想；没有移植 Stockfish 源码。

## 适配与边界

- 使用有上限的直接映射槽表，默认 1,048,576 条。索引碰撞后核对完整局面字符串，碰撞只能导致未命中，不能把另一个局面的结果拿来用。条目不保存棋盘对象或走法的 `_n` 子局面。
- 局面身份复用 `posKey`，包含全部棋子类型/颜色/位置、消失标记、行棋方、易位权、吃过路兵格、双方弹药；另加半回合计数。冻结、透明、黑暗等效果由盘面推导，不复制规则。总回合号和 `_cap` 不影响当前规则或评估，不作为缓存身份。
- 打入、打入费用、升变、易位、吃过路兵和兵双步均纳入缓存走法签名；2026-10-28紧凑表示上线后，签名直接使用压缩整数，不再序列化/解析走法数组。每次仍从当前生成的走法中匹配，走法继续经过原合法性检查，不执行缓存中的旧子局面。
- 记录剩余深度、评分、精确值/下界/上界、走法、代数。跨根节点使用将杀分数时校正 ply 距离。
- 主搜索默认复用**相同或更深剩余深度**的评分；`PRUNE.ttDeep=0`保留仅相同深度的对照模式。较浅或评分边界不适用的记录仍可用于走法排序。深结果复用可能改变固定浅层搜索的值，不宣称与原策略全局等价。静态搜索入口保持独立身份和原深度条件，不新增内部Q缓存。
- 当前引擎仅在根相对 ply 1/2 检查实际历史重复。缓存对 ply 0/1/2 隔离根距离和完整历史集合，历史先做完整比较再分配版本号；更深节点可跨回合复用。本次不修改原重复或 50 回合规则，也不借缓存修正规则问题。
- 评估开关、权重、子力估价/价格和剪枝参数改变时清表。超时异常不会将尚未完成的节点写成精确结果；已完整算出的子节点可以保留。

这不是完整保存搜索树。新回合仍从浅层迭代加深，命中缓存时减少重复搜索。缓存改变排序，在选择性剪枝或限时条件下可能改变最终落子，不保证任何配置下都走同一手。

## 生命周期与接口

`timedMove`、固定深度选着入口和分析搜索均接入。电脑对弈每个游戏会话拥有一个可复用 Worker，完成一手后保留；取消进行中的搜索仍销毁 Worker，阻止过期结果。重新部署、新局、销毁会话会释放 Worker。分析面板的无限分析 Worker 仍在切换局面时销毁，面板当前主要获得同一局面内的复用，不宣称面板已跨局面保留缓存。

- `TT.enabled`：缓存总开关；`timedMove(..., {tt:false})` 可单次禁用。
- `TT.slots`：槽数，下次搜索检测变化并清表；上限 1048576。
- `PRUNE.ttDeep`：默认1，允许更深主搜索评分满足较浅请求；设0用于精确深度对照。切换会使缓存配置失效。
- `clearTranspositionTable()`：清空表与统计。
- `transpositionStats()`：累计 probes/hits/cutoffs/stores、条目数、容量、代数。
- `withSearchCache(fn, {hist, enabled})`：为固定局面研究提供显式缓存作用域。调用方的 `setSearchState` 重复历史必须与 hist 一致。直接调用原始 `negamax` 保持无缓存，可作对照。

Windows 旧版实验未更新、未重启，其结果不与新版混合。本机 Stockfish 八局在此实现前已完成，未新增对局或改写其结果。未来在新源码上续跑旧实验会被原有摘要校验拒绝，应使用新输出目录。

## 验证与小规模性能记录

```sh
npm run build && npm run test:all
node --import tsx tests/transposition-bench.mjs
```

新增测试覆盖 20 个金标准局面的固定深度开关对照、连续走棋、特殊状态身份、完整走法签名、上下界、历史隔离、将杀距离、权重/模式切换、容量碰撞、超时、Worker 保留与取消。金标准不修改。真实 Worker 测试连续提交两次搜索，检查缓存仍保留。

2026-10-25 本机一次三局面试验，内部 futility/LMR 关闭、原有根候选收窄保留，每次 3 秒：

| 局面 | 关闭 TT | 冷 TT | 同局面热 TT |
|---|---:|---:|---:|
| 香草开局 | 5 | 5 | 5 |
| 灵梦透明穿透 | 5 | 5 | 5 |
| 爱丽丝可打入 | 5 | 6 | 6 |

固定四层的三局面评分也一致。冷表耗时分别约为无表的 99%、106%、91%；表查找本身有成本，并非所有局面都更快。同局面固定深度热表命中只访问一个搜索节点，不等于真实下一回合也只访问一个节点。该试验每项仅测一次，顺序可能受 JIT/机器负载影响，不是统计性能结论，更不是棋力结论。原始数据在 `lab/out/transposition-bench.json`。

2026-10-28的[完整组合实验](TT_INTERACTIONS.md)在6/9层七局面中测得，1M槽加深结果复用使节点减少19.8%，两批耗时分别减少13.6%和16.7%。用户已据此授权成为默认；[上线与紧凑表示后续测试](COMPACT_REPRESENTATIONS.md)记录了验证边界。该收益不等于已测定棋力提升，也不保证所有局面/设备同比提速。
