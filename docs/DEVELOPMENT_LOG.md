## 交接背景：从单文件原型拆分

项目是每方 45 点预算、16 个初始身位的国际象棋变体。部署位置分王位、后位、车位、轻子位和兵位。

原型是单文件 HTML。重构时先保留行为，再拆分规则、搜索和界面，使用金标准防止搬迁过程中发生规则漂移。

### 架构与职责

| 目录 | 职责 |
|---|---|
| `rules/` | 规则书、结构化棋子表 |
| `engine/` | 唯一可维护的 TypeScript 规则、评估和搜索实现 |
| `cli/` | 调用引擎执行批量对局，输出 JSONL |
| `lab/` | Python 实验编排、统计、标定及调参 |
| `tests/` | 金标准、回归和性能实验 |
| `web/` | Svelte 5 + Tailwind + Vite 前端及构建产物 |

用户的应用技术栈是 Python / Django REST Framework、Svelte 5 和 Tailwind。前端使用普通 JavaScript，方便用户参与外观调整及少量交互逻辑开发。助手负责主要实现，不能将“用户会改界面”作为留下未完成功能的理由。

引擎使用 TypeScript，因为它需要直接运行在浏览器中。Python 研究工具通过薄 Node CLI 调用同一引擎，不复制棋规或搜索。DRF 是业务后端的技术选择，当前尚未实现业务后端。

### 单一引擎实现

`engine/index.ts` 是公共入口。页面、分析 Worker、电脑选招 Worker 和研究工具复用 `engine/`。

`web/engine.js`、`web/engine.mjs` 和根目录 `touhou-chess.html` 都是生成物，只能通过构建更新。禁止在页面、Worker 或 Python 中另写一套引擎。`archive/` 仅保留交接前原型，不作为开发、运行或测试入口。

### 部署价格和引擎估价分离

- `cost`：规则规定的部署价格，来自 `rules/pieces.toml`。
- `value`：引擎判断棋子价值时使用的估价，由 `engine/weights.json` 覆盖，未覆盖时等于 cost。

旧原型用同一字段同时表达价格和估价，导致“调整被测棋子价格”同时改变预算与引擎判断，实验效应无法分离。拆开后，应先研究正确估价，再单独研究是否调整部署价格。

### 永琳与开发者级

两者使用同一实现。永琳启用手写开局原则；开发者级关闭中心、堵塞、发展、重子早出和易位位置等开局项，保留子力、活动能力、王安全和残局驱动。

原 README 记录的历史实验中，重子早出扣分在香草阵容上带来 +21.7 个百分点，而在灵梦三枚阵容上为 −20.0 个百分点（样本数分别为 60/80）。这些数字是交接实验记录，本次未重跑；具体可信度与后续结论见 [研究记录](RESEARCH.md)。

开发者级通过 `devMove` / `devMoveAt` 统一关闭并恢复开局项，避免研究脚本忘记切换。开发者级仍含启发式评估与根节点候选收窄，不能当作无偏或完全精确的测量仪器。

八云紫平衡暂缓；开发者级与永琳合并需要研究证据及用户决定，不自行合并。

### 仪器先于测量

历史验收使用“香草少 k 个兵对完整香草”，双方无打入能力，省下的弹药无法花掉，确保是真让子。预期同阵容约 50%，少一兵明显下降，少三兵更低。

原 README 记录：深度 2 对少 1/2/3 个兵的测量得到 47.5 / 48.3 / 47.3%，未显示合理趋势。此前约六千局子力标定因此作废。不要仅凭程序可运行或金标准通过，认定引擎足够可靠，可用于定价。

原 README 还提到 `rules/open_questions.toml`，但本次整理时仓库中不存在该文件，不将它作为可用的检查入口。待决问题应结合现有规则、研究记录及用户决定处理。

### Python 环境和开发命令

所有 Python 脚本使用 Miniconda 同名独立环境 `TouhouChess`，禁止系统 Python 和 base。环境定义在根目录 `environment.yml`，当前 Python 3.12，研究工具使用标准库。

以下命令均在项目根目录执行：

```sh
conda env create -f environment.yml  # 仅首次创建
conda activate TouhouChess

npm run build && npm run test:all
npm run rules
conda run -n TouhouChess python lab/accept.py
npm run h2h
npm run firstmove
```

`npm run rules` 对应规则解析、成本表生成和检查。固定深度与等时对局、参数搜索和样本量判断见 [实验计划](EXPERIMENT_PLAN.md)；研究脚本修改模块导入时的辅助工具为 `conda run -n TouhouChess python lab/fiximports.py`。

金标准验证的是既有行为，不证明棋规无漏洞或棋力足够。不得修改金标准来掩盖回归；规则变动需要授权并解释基准变化。

## 2026-10-25：提高深度和限时选招

| 档位 | 目标深度 | 每手搜索预算 |
|---|---|---|
| 琪露诺 | 3 | 0.5 秒 |
| 霖之助 | 4 | 1 秒 |
| 帕秋莉 | 5～7，少子时加深 | 2 秒 |
| 永琳 | 无固定深度上限，迭代加深 | 3 秒 |

前三档保留原来的随机失误和次优走法概率。超时采用最后完整迭代的结果，发现将杀或仅剩候选时可能提前结束。时间预算是周期检查的软限制，不是硬实时保证，Worker 启动另有开销。

电脑选招移入独立 Worker。悔棋、重新部署、切换电脑执方或难度会取消旧搜索并丢弃迟到结果。Worker 不可用时提示失败，不回退到阻塞界面的深搜。

固定深度研究 API 保留。开发者级固定深度默认提高为 4～6 层；旧实验复跑必须显式指定原来的深度，避免与新默认混用。当前两种评估模式仍独立保留。

验证：构建通过；源码与产物共 610 项金标准、150 项集成断言，以及新增限时搜索、超时回退、取消和真实 Worker 测试通过。

## 2026-10-25：futility + LMR 三秒预算实验

只在独立实验进程中切换 `PRUNE.inner`，未修改默认值，默认仍为 `0`。保持永琳的其他配置及根节点候选收窄不变，使用 Apple M2 / Node.js，六个局面各三组配对。同组使用相同随机种子，交替测试顺序，串行运行以避免实验之间抢占 CPU。

| 局面 | 关闭内部剪枝 | 开启 futility + LMR |
|---|---|---|
| 香草开局 | 5 | 7 |
| 香草展开后 | 4 | 6 |
| 灵梦穿透局面 | 5 | 6～7 |
| 爱丽丝可打入 | 5 | 7 |
| 王车对王 | 7 | 9 |
| 兵残局 | 10～11 | 12 |

18 组配对共 36 次搜索，16 组增加 2 层、2 组增加 1 层，平均增加 1.89 层。耗时 3000～3010 毫秒。比较的是完整迭代深度，不代表每条分支搜索深度，也未验证胜率提升。

- [原始结果](../lab/out/timed-prune-3s.json)
